# DalaHold · кликабельный UX-прототип

Для локального API и сохранения **только черновиков условий** запустите из корня проекта:

```sh
node web/server.mjs
```

Откройте <http://127.0.0.1:4174/>. Черновики, их прежние версии условий и метки документов без файлов сохраняются в `.local/drafts.sqlite` на этом компьютере и доступны после перезагрузки страницы и сервера. Кнопка «Изменить черновик» создаёт новую версию, только если открытая версия не устарела; при конфликте другая вкладка не перезаписывается. Старые базы черновиков автоматически получают версию 1 без удаления условий. Сервис слушает только `127.0.0.1`; в нём нет аутентификации, поэтому используйте исключительно вымышленные или обезличенные данные. Профили продавца и покупателя в сохранённом черновике — тестовые подписи, не реальные участники.

Каждая версия получает SHA-256 отпечаток канонических байтов: ID сделки, номер версии, товарный сценарий, количество, сумма и срок. Он позволяет сравнить, одинаковы ли эти поля, но **не доказывает**, кто их ввёл, согласовал или подписал, и не защищает локальную базу от изменения.
Для текущей версии также показываются отличия от предыдущей. Повторное сохранение тех же полей не создаёт новую версию.

Для прежнего полностью статического макета можно открыть `index.html` либо запустить:

```sh
cd prototype
python3 -m http.server 4173 --bind 127.0.0.1
```

Затем откройте <http://127.0.0.1:4173/> на этом компьютере. В статическом режиме черновик существует только до обновления страницы. Сборка и установка пакетов для веб-кабинета не нужны.

Для полного прогона: продавец отправляет предложение → переключение тестового аккаунта → покупатель принимает и удерживает демо-₸ → продавец заявляет передачу → покупатель принимает либо открывает спор → при приёмке смоделирует расчёт → обе стороны могут оставить отдельные демо-отзывы. Все эти шаги остаются браузерной имитацией и сбрасываются после обновления страницы или смены версии условий. Переключатель «Зерно» показывает альтернативную партию; «Новая сделка» создаёт черновик, который сохраняется только в режиме локального API. Раздел «Кошелёк» показывает концепцию смены метки сертификата.

В карточке сделки вкладка «Документы» показывает примерный набор для КРС или зерна. Кнопка «Добавить в макет» позволяет выбрать **тестовый или обезличенный файл** и отметить его раздел и партию/отгрузку. Содержимое файла не считывается и не загружается. В статическом режиме имя и размер видны лишь до обновления страницы. Для сохранённого черновика API записывает категорию, версию условий, формат по расширению, тестовую роль и введённые описания; **выбранное имя и содержимое файла автоматически не сохраняются**. Не вписывайте личные данные или имена файлов в описания: они сохраняются как введены. Метки старой версии остаются в архиве и не переносятся в новую версию автоматически. Запрос с устаревшей версией отклоняется, повтор с тем же ID не создаёт вторую запись. Это не защищённое хранилище, не передача файла второй стороне и не проверка его подлинности или автора. Локальный API без аутентификации; не вводите реальные данные.

Зерновая ветка не моделирует качество, вес по машинам и частичную приёмку. Один реальный профиль сможет работать в обеих ролях в разных сделках; переключение ролей здесь показывает **два тестовых аккаунта одной сделки**, а не возможность заключить её с собой.

Локальный API не связан с `workflow/DealFlow`: тот принимает только доверенные тестовые данные и не должен превращаться в публичный маршрут создания подписанной сделки. Кнопки не вызывают NCALayer, не создают ЭЦП, не отправляют Solana-транзакции и не перемещают деньги. Все имена и оценки вымышлены. Решение о первом товарном сценарии ожидает разговоров с реальными парами участников.
