# Spike 012: strict TEST OCSP

## Scope and acceptance

Baseline: pushed `main` at `acc193c8df402370ef59784865e47f45e2280de3`.
Keep the CRL gate intact. OCSP is a separate explicit TEST mode, not a
fallback after failed verification. No personal key, production CA, wallet,
corporate permission, deal decision or payment is authorized by a test receipt.

Require issuer/responder trust and purpose, matching responder ID, response
signature, exact request CertID and 32-byte nonce, fresh timestamps and good
status. Missing/changed nonce, foreign issuer/responder, revoked/unknown,
old/future response, critical extensions, malformed/oversized input and
network failures must refuse. Expiry and source must remain bound at commit.

## Research

Checked 30 September 2026: [RFC 6960](https://www.rfc-editor.org/rfc/rfc6960.html#section-3.2)
defines response acceptance and direct issuer delegation; a delegated responder
also needs a revocation policy. This spike requires a validated noCheck
extension or refuses it. [RFC 9654](https://www.rfc-editor.org/rfc/rfc9654.html#section-2.1)
updates nonce encoding/length; use a random 32-byte nonce and require its echo.
The 5-minute age limit and 60-second skew are this test stand's conservative
local policy, not an assertion of NCA's official validation rules.

| Approach | Benefit | Limit | Decision |
|---|---|---|---|
| SDK OCSPUtil.verify | Existing utility | Omits responder trust, CertID and freshness checks | Not an acceptance gate |
| SDK ASN.1/OCSP primitives + explicit checks | No new dependencies; testable signed responses | Must validate every boundary and review it | Use in separate test mode |
| New OCSP service/dependency | Potential wrapper | New compatibility/deployment boundary | Defer |
